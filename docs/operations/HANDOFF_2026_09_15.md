## TASK 1 — INTERACT close-up (broken, this is the priority)

### What INTERACT is meant to be

The user's spec, in their words: it should feel identical to SPEAK — a zoom in,
resolving into a close-up **first-person view of the object**, "like the camera
OF the object", framed so you can act on it. Choices are generated there like a
normal frame. Exiting returns you to your scene — **regenerated**, because you
changed the world, but img2img off the frame you were in before you interacted.

> "this is the cool feature of interaction vs move, the result is a changed
> version of the original scene"

MOVE is a hard cut to somewhere new. INTERACT is the same place, altered. The
verbs are only worth having side by side if that difference is visible.

A wide shot of the player working the object is the correct **result** frame.
It is not the dive.

### State: the dive never opens

Built and present but **not working**:

- `standalone.js:~21240` — `Moments.register("interact", {enter, exit, onEsc})`,
  whose `enter()` fetches the close-up plate and calls `Moments.setPortrait()`.
- `standalone.js:21272` — `openInteractMoment(obj)`, holds the Moment open then
  pops.
- `standalone.js:20041-20044` — the call site, immediately before `makeChoice`.

Evidence from the last run (`metal stand -> INTERACT`, resolved 25.1s):

- **No `/api/talk/portrait` request reached the server at all.**
- **Zero client console errors** — so `Moments.push` did not fail (its failure
  is caught and warned).
- **The turn committed normally** — so nothing threw before `makeChoice`, which
  rules out `openInteractMoment` being an unresolved identifier at the call
  site (that would have thrown a ReferenceError and blocked the commit).

The function therefore neither ran nor threw: **the guard short-circuited.**

```js
if (action.id === "interact" && window.Moments &&
    typeof window.Moments.push === "function") {
  openInteractMoment(obj);
}
```

### Do this first

Replace that compound guard with an unconditional call in a try/catch, logging
which conjunct was false:

```js
console.warn("[interact] gate", action.id, !!window.Moments,
             typeof (window.Moments || {}).push);
try { openInteractMoment(obj); } catch (e) { console.warn("[interact] threw", e); }
```

One run tells you whether it's the guard or a scoping problem. **Leading
hypothesis:** the registration block and `openInteractMoment` were appended
directly after the `conversation` registration, which may sit *inside* the
`Talk` module closure rather than at module level — in which case they are
scoped wrong and need moving out to where the other Moment types register
(`standalone.js:22051` for `encounter`, `:22447` for `cutscene` are the models).

### Then: the framing

The plate currently requests `/api/talk/portrait`. Contract is at
`engine.py:11639`:

```
POST /api/talk/portrait
{"subject": {"label","kind","speaks","cx","cy","w","h"},
 "reference_image": <data url>, "reference_cropped": bool}
-> {"image_url", "mode", "prompt", "companion"}
```

The scan detection is passed whole so the server crops from the object where it
sits in frame (`subject_crop`) rather than imagining one from the label. Keep
that. **Unverified:** whether this endpoint produces a good close-up for an
*inanimate* subject — it was built for TALK, where subjects are people.
`object_subject` exists in the image layer for exactly this case
(`gemini_image_utils.py:390,416,1151,1350` — close-up of a machine/object, with
an anti-person rule so the model cannot invent a face on a thing). If the
endpoint doesn't already route to it based on `kind`, wire it through.

### Then: the lingering glow (a real bug the user reported)

> "the glowing overlay transition graphic renders for a while AFTER the image
> loads from interact"

That's mine. `openInteractMoment` polls every 500ms for the turn to settle and
then pops, so the result frame lands *first* and the overlay outlives it. With
no plate ever arriving, the user was staring at an empty `developing` shimmer
the whole time.

Fix: pop on the scene-painted signal instead of polling. `markScenePainted()`
already exists and is what the boot gate waits on. The close-up should hand off
to the new frame on the same beat, not race it.

### Then: choices in the dive

Not built. There is no endpoint for object-level choices. The turn's own new
choices are what you currently get when the Moment pops. This is a gap in the
spec, not a finish.

## TASK 2 — Flipbook is untested because it never turns on

`tunables.py` holds knobs on disk in `tunables.json` and its docstring promises
they "survive a restart". They don't: `apply_all()` (`tunables.py:291`) pushes
stored values into engine module globals, and **nothing calls any `tunables.*`
function in `engine.py` or `play.py`.** So `FLIPBOOK_ENABLED` stays at its
module default of `False` (`engine.py:1308`) no matter what is on disk, and
flipbook is reachable only by toggling it live through the browser-reachable
store mid-session.

`tunables.json` currently has `flipbook_enabled: true` sitting in it, waiting
for something to read it. A 3-turn run with it set produced zero flipbook lines
in the server log and behaved exactly like a normal stills session.

Fix is one call to `tunables.apply_all()` at boot — most likely in `play.py`
after the engine import, since engine appears not to import tunables at all
(the dependency runs the other way; check before placing it, and watch for an
import cycle and for applying before the globals it writes exist).

Then actually test flipbook; nothing about it has been exercised.

## TASK 3 — Encounter UI (cheapest win available)

The user's complaint: text in the top left, text in the top right, and "terrible
outline boxes" around the buttons; wants it unified, minimal, elegant.

**The design they're asking for already exists and is simply never switched
on.** `static/css/standalone.css:5342-5405` has ~60 lines scoped to
`body.moment-encounter` doing exactly that — `border: none`, `background:
none`, `box-shadow: none`, sentence-case typography set over the frame, with a
comment explaining that lane-coloured boxes "made a confrontation look like a
menu."

**`body.moment-encounter` is never applied anywhere** — it appears in no `.js`
or `.html` file in the repo. So encounters fall through to the base
`.moment-choice` panel style at `:5029`, which is the bordered-box look. The
split-personality text the user noticed is the generic Moment chrome showing
instead of the encounter treatment.

Apply the class when an encounter Moment opens and remove it on pop (the
`encounter` type registers at `standalone.js:22051`; `enter`/`exit` are the
hooks). Then reconcile the two text blocks — `#moment-nameplate` (name + sub,
`templates/standalone.html:840`) against the now-live styling.

## Verified working this session (don't re-fix these)

- **The turn watchdog no longer eats good turns.** It was 26s while a healthy
  scan/move turn takes ~29-30s, so it fired *before* the good turn landed and
  printed "The world hesitated. Choose again." over a turn that then arrived.
  Now 45s plus a liveness check: `state.lastId` (feed cursor) only advances when
  the server emits an item, so if it moved we extend rather than interrupt,
  bounded by `TURN_WATCHDOG_MAX_EXTENSIONS = 4`. Confirmed: a 29.6s interact
  turn produced zero hesitations. The harness now *fails* on a hesitation that
  appears on a turn which subsequently resolved.
- **INTERACT commits as a turn.** It was a dead button: the action is declared
  `realtime: true` and `Renderer.steerRealtime()` returns truthy for a steer it
  merely *accepted*, so on stills the handler toasted and returned without
  committing. Now gated on `scanInRealtime()`, so stills falls through to the
  full turn. Verified: `desk -> INTERACT` resolved in 29.6s.
- **INTERACT is offered at all.** `interactEnabled()` was a flat `false`; every
  scan offered only `['move']`, which is why the world felt like scan-and-
  teleport. Now on for stills, still shelved under live video where the original
  reasoning holds. Verified: `sub-actions: ['move', 'interact']`.
- **The server side of "changed version of the same scene" needed nothing.**
  `engine.py`'s `elif interaction` branch is "the refine-from-current path...
  the only place a soft continuation is still allowed", so an interact turn is
  already img2img from the frame the player was in. `engine.py:15551` forces
  `hard_transition = True` for MOVE, deliberately.
- No black screens in any run this session.

## Still open, root-caused, not fixed

Details in `CHANGELOG.md` (top of file):

1. **Custom action never reaches the camera.** Resolve plate is minted at
   `encounter.py:3633`, narration written at `:3673` — 40 lines later, from the
   same inputs independently. A custom action ("set the man on fire") gets a
   plate that ignores it. Fix: narrate first, pass it to the image prompt.
2. **Encounter conclusion gets painted over**, and **flickers** result →
   original standoff plate → result.
3. **Encounter hard cut is ~9s of pure black.**
4. **MOVE onto an object already on screen teleports you** (`engine.py:15551`).
   Fix: soft branch if the target is in the current frame's object list.
5. **Encounters can kill in two rounds.** A forced encounter on turn 4 ended a
   15-turn run at 27% completion. Design call, not a bug — but the harness used
   to always pick choice 1 (the confront lane, most lethal) and now rotates
   lanes, so re-measure before tuning.
